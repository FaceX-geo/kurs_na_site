# Пакет проектирования и миграции «Курс на Север»

Дата фиксации: **29.07.2026**.

## Вывод

Новый сервис следует проектировать как три согласованных, но разделённых
контура:

1. публичный сайт и CMS;
2. CRM с отдельными воронками «Переезд» и «Студенты»;
3. независимый модуль управления направлениями, проектами и задачами.

Договор не содержит полноценной ERP: финансового учёта, бюджетирования,
закупок, склада, бухгалтерии, расчёта зарплаты и кадрового контура. Добавлять
эти функции в обязательный объём без отдельного решения Заказчика нельзя.

Bitrix-дамп пригоден как источник данных, но недостаточен для полного переноса:
SQL содержит метаданные 3 941 файла, а сами бинарные файлы должны быть получены
отдельным согласованным снимком `/upload` или фактического файлового хранилища.
Текущая доказуемая capability — только `PARTIAL_ONLY`: одного `/upload`
недостаточно без общего DB/upload freeze watermark, 100% ACL/storage
reconciliation, versioned decode `b_disk_right.TASK_ID`, решений unknown
principals/orphans и signed outcomes для двух legacy external links. Любой
waiver даёт только `PARTIAL_MIGRATION_ACCEPTED`, а не FULL.

## Обязательные решения до реализации

1. Подтвердить, означает ли слово «ERP» дополнительный объём или договорный
   проектный модуль.
2. Утвердить стадии двух воронок, формы, поля и причины завершения.
3. Согласовать матрицу прав `resource + action + scope`.
4. Утвердить mapping Bitrix → target, правила дедупликации и survivorship.
5. Получить синхронный снимок SQL и файлового хранилища.
6. Утвердить обработку персональных данных, внешних провайдеров и retention.
7. Зафиксировать критерии сверки, cutover, rollback, RPO/RTO и SLA.
